Vibe Coding · Debugging practice

Turn “fix this” into a useful debugging prompt.

AI can suggest better fixes when you give it evidence from the failure and keep the request narrow. Your job is to choose the context that helps an assistant act on the diagnosed cause instead of guessing.

Observed state means what the app’s data or behavior actually looked like at the moment it failed.

Practice: build the debugging request

Exercise scenario
A profile card goes blank when the service returns no user record.
Console TypeError: Cannot read properties of null (reading 'name') at renderProfile (profile.js:42)
Relevant line nameEl.textContent = profile.name;
Observed state profile === null
Goal Keep the card visible and show “Profile unavailable” when no record is returned.
Choose what to include in the AI request.
Select the evidence and scope you would give the coding assistant, then check your request.

Your request

Fix this error.

Simulated result

With almost no context, the assistant has to guess which code and behavior matter. It may propose a broad rewrite instead of a targeted fix.

This is a deterministic local preview, not a live AI model.

Play: change the context, watch the suggestion change

No single “perfect wording”

There is no single right answer here. Compare the trade-offs and notice what changes as the request becomes more or less grounded.

Focused

The assistant can connect the crash to the null value and propose a small fix at the relevant access point.

Example output: “Check for a null profile before reading profile.name; keep the existing card and render the fallback text when the record is missing.”
